## 2. 编码器与校准结论

### 2.1 极对数与 CPR（mode 6 实测）

两次 mode 6 结果：

| 次 | delta | pp_meas | slip | 每电周期计数 |
|---|---|---|---|---|
| 1 | -4092 | 10.00 | 0 | 391~428 |
| 2 | -4095 | 10.00 | 0 | 393~427 |

结论：

- CPR=4096 正确
- 实际极对数 **pp=10**（不是之前怀疑的 12）
- 编码器与转子无打滑/回差（整圈 delta≈CPR）
- 每电周期 391~428 的波动来自齿槽造成的瞬时位置起伏，整圈累计抵消

### 2.2 电角度方向与 offset

- `CFG_MOTOR_POLE_PAIRS = 10`
- mode 3/7 实测 `moved > 0` → `g_enc_elec_dir = -1`（编码器计数增对应电角度减）
- mode 3/7 的 offset = ALPHA 保持结束时的 `count mod CPR`
- mode 3 单步两点法的 moved 长期在 80~100（理论 102.4）：
  - 转子会停在“磁力矩 + 齿槽力矩”的 detent 上，BETA 端点常短 10°~15° 电角度
  - moved 幅值只用于 dir 符号，offset 由 ALPHA 端点决定；同一机械位置重复性很好（offset 15/16 等）
  - 换机械位置后 offset 折算到一个电周期（409.6 counts）会有几十 counts 的散布
- mode 7 斜坡（0→90→0）没有消除 detent：hold 200ms/1000ms 的 beta/alpha 完全一致，说明是静态平衡点，不是没稳
- 结论：**offset 可用，但受齿槽 detent 影响，精度约 ±几度~十几度电角度**；mode 4 不再强求 moved≈102

### 2.3 编码器电角度折叠 bug（已修）

日志曾出现 `th=-2867°`。原因：

```c
e = c * (2π/CPR) * pp;
if (dir<0) e = 2π - e;          // 大角度时 e 变成大负数
if (e >= 2π) { ... }            // 负数不进折叠
if (e < 0) e += 2π;             // 只加一个 2π，仍为负
```

修复（`hw_encoder.c`）：**先按 dir 取反，再恒定时间折叠**：

```c
e = ...;
if (g_enc_elec_dir < 0) e = -e;
e -= 2π * (int32_t)(e / 2π);
if (e < 0) e += 2π;
if (e >= 2π) e -= 2π;
```

现在 `th` 显示在 0~360°。

## 3. 电流采样与零偏

### 3.1 板型与引脚

`CFG_SAMPLING_BOARD_IU_SENSOR = 1`：

| 引脚 | 通道 | 角色 |
|---|---|---|
| PA3 | ADC_CH3 | iu |
| PA4 | ADC_CH4 | iw |
| PA5 | ADC_CH5 | iv |
| PA6 | ADC_CH6 | vbus |

### 3.2 极性

低侧 shunt 采样，运放方向与 FOC 相电流正方向相反。mode5 实测三相电流矢量整体差 180°，因此：

```c
#define CFG_SAMPLING_CURRENT_SIGN  (-1.0f)
#define CFG_SAMPLING_CURRENT_SCALE ((CFG_SAMPLING_CURRENT_SIGN) * (3.3/4095) / (6.0 * 0.02))
```

注意：这行 sign 曾在某次修改中丢失，导致 mode4 的 id 越调越负、iq 上不去；已恢复。调 mode4 前务必确认该宏存在。

### 3.3 零偏校准

1. 上电：`PowerOn_OffsetCal()`，PWM 关闭，三相读零偏（Watch 可见 `g_cal_offset_*`）
2. 进 mode4/8：`Foc_CurrentLoop_Reset()` 里启动一次 **50/50 零矢量在线校准**：
   - 预热 210ms（4200 拍）内，前 2000 拍（100ms）累计原始 ADC
   - `Motor_Sampling_ApplyOffsetCalSilent()` 静默更新 `s_scale.current_offset[]`
   - 若进环时转速 >50 rpm，则跳过重校，保留上电值
3. 日志里能看到：预热前段 iq/id 带约 0.3~0.5A 旧偏置，校准完成后掉到 ~0

### 4.1 重要经验：积分限幅不能低于 vmax

曾把积分项限在 **3.0V**，而输出限幅 3.5V：

- 稳态需要 3.5V 时，积分只能给 3.0V
- 剩余 0.5V 必须由 P 项补，`error = 0.5/0.27 ≈ 1.85A`
- 结果 iq 平均值远低于 iq_ref（droop）

参考工程注释也写了“积分项限幅必须 > 运行时反电动势”。参考工程的 `FOC31_INTEGRAL_MAX=3.0` 实际限的是积分量 A·s，没真正生效，等效只受 3.5V 输出限幅。当前取 **iterm_max = vmax = 3.5V**，既可撑满电压，又不会积分超过输出。

### 4.2 实测：空载高速会电压饱和

mode4 空载、iq_ref=1500mA，稳定在约 3770~3870 rpm：

```
vraw = 3.94 ~ 4.83V（PID 想给）
vmax = 3.5V
lim  = 2（CL_LIMIT_VOLTAGE）
spd  ≈ 3770~3870 rpm
```

按电机参数，3870 rpm 时：

- 反电动势峰值 ≈3.4V
- `R·iq ≈ 0.15V`
- `ωe·L·iq ≈ 0.26V`
- 总需求 ≈3.56V > 3.5V

所以电流环已经顶满，iq 无法维持。**这不是环路 bug，是电压/反电动势物理限制。**

把 `g_cl_iterm_max_watch` 改成 6（而 vmax 仍 3.5）只会让积分 windup 到 6V，`vraw` 冲到 8V，抖动更大；正确做法是同时提高 `g_cl_vmax_watch` 和 iterm。

### 4.3 推杆应用的力矩模式判断

- 低速/顶住负载/堵转：反电动势≈0，1.5A 只需约 0.15V，iq 能稳定跟随 → **恒力矩，力矩模式 OK**
- 空载高速：电机会一直加速到反电动势顶到 vmax，iq 自然会掉到摩擦电流（约 0.5A）
- “空载 + 恒定 iq + 恒定转速”三者不能同时成立；要恒速需加负载或速度环
- 推杆的受力工况一般是低速/堵转，因此当前 mode4 已可覆盖；空载飞车需加速度限制/保护

## 5. mode 8：电流环 + dq 解耦 + 反电动势前馈（新加）

### 5.1 目的

- mode4 保持纯 PI，作为基线
- mode8 在 PI 输出上叠加已知电压项，减少高速时 id/iq 交叉耦合和积分负担

### 5.2 前馈公式

```c
we = rpm * (2π * pp / 60);          // 电角速度，rpm 来自编码器（已按 dir 取正方向）

vd_ff = -we * Ls * iq_fb;
vq_ff =  we * Ls * id_fb + we * flux + Rs * iq_ref_ramped;

vd_tot = vd_pi + vd_ff;
vq_tot = vq_pi + vq_ff;
```

其中：

- `Ls` 用 `g_cl_ff_ls_uh (µH)` 转 H
- `flux = g_cl_ff_flux_vs`
- `Rs = g_cl_ff_rs_ohm`
- 默认：Rs=0.1Ω、Ls=42.3µH、ψf=0.00084 V·s（参考工程同一台电机）

### 5.3 输出处理

- `s_vmag_raw` 改为 **PI + 前馈的总需求幅值**，用于 `lim=2` 电压饱和判断
- 最终 `(vd,vq)` 做**矢量限幅**到 `s_vlim`（=vmax，默认 3.5V）
- FF 开关：`g_cl_ff_enable`（mode8 进入时置 1，mode4 置 0）

### 5.4 Watch / 观测量

| 变量 | 说明 |
|---|---|
| `g_cl_ff_enable` | 1=开启 |
| `g_cl_ff_rs_ohm` | 相电阻 Ω |
| `g_cl_ff_ls_uh` | 相电感 µH |
| `g_cl_ff_flux_vs` | 磁链 V·s |
| `g_cl_we_rad_s` | 观测：电角速度 |
| `g_cl_vd_ff` / `g_cl_vq_ff` | 观测：d/q 前馈电压 |

10ms 打印已追加：

```
ff=%u we=%ld vffd=%ld vffq=%ld
```

### 5.5 使用方法

1. `g_mode_cmd = 8`
2. 前置条件与 mode4 相同：已对齐、零偏已校准、非 LATCHED、vbus>6V
3. 进环后同样先 50/50 校准零偏，再闭环
4. 与 mode4 对比同一 `iq_ref`、同一转速下的 `id/iq` 抖动与 `vraw`

### 5.6 预期效果

- id 更贴近 0（交叉耦合被前馈抵消）
- iq 跟随更好、积分不容易顶限幅
- 不会突破电压上限：需求 > vmax 时仍然饱和；空载仍会加速到反电动势极限
- 高速段仍需保证 `vmax` 足够，建议 `vmax = iterm_max`（如 5.0/5.0）

## 6. 当前已知问题 / 后续

1. **高速电流环带宽**：20kHz 采样、约 1kHz 带宽、EMA α=0.3；645Hz 电频率时相位裕度紧张。mode8 前馈可改善，若仍抖可临时把 `g_cl_fb_alpha` 提到 0.5~1.0。
2. **offset 齿槽偏差**：mode3/7 的 offset 会随机械位置有几十 counts 散布；后续可做多点 offset 圆周平均。
3. **空载飞车**：推杆应用建议加速度上限/行程保护；或加简单速度环。
4. **堵转热保护**：恒力矩堵转 1.5A 长时间要注意电机/驱动器温升。
5. **mode8 尚未实测**：先用 2000~3000 rpm、1A 左右对比开关前馈前后的 `id/iq/we/vff*`。
6. **模式日志**：`[CL]` 行同时用于 mode4/8，用 `ff=` 和 `CURRENT_FF` 进入日志区分。
