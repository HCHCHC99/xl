# 测试用例：业务层（模块级 · 台架模拟）

- 适用固件：2026-11-20 及以后（含 `t_sim` / `t_bench` / `t_seq` / `t_canrx` / `t_swing`）
- 目的：在没有钥匙、没有可调电源、没有 CPB 面板、没有 CAN 仪的条件下，验证业务链路
  （判据 → 门禁 → 状态机 → 动作 → 输出 → 反馈）的**判定与状态迁移**。
- 边界：**不验证功率输出**。`t_sim` 只喂"读数"；电机驱动未接业务层（P0-2），
  举升阀只发 CAN 帧。要转电机请用 `focmode` 直控。
- 工具说明见 `任务清单.md` §11；存储/欠压专项见 `测试用例_批次1_2.md`。

---

## 0. 每轮固定前置

**每次复位/重新烧录后 `t_sim` 全部清零**，必须先跑：

```
t_bench
```

等价于（每步间隔 1 s，最后等 1.2 s）：

```
t_sim cansilent 0      # 无真实 CAN 时必做，否则 2s 后整车 FAULT
t_veh_clr
t_sim bus 13200        # >13.0V
t_sim acc on           # 500ms 去抖
```

通过判据：`[bench] OK: STARTED, ready for test`。
失败会打印 `NOT READY` 并附 `state/started/acc/fault/volt`。

> 踩坑记录：2026-11-20 两次漏掉 `cansilent 0`，都得到 `[VEH] -> FAULT (word=0x1)`。

## 1. 观测命令

| 命令 | 看什么 |
| --- | --- |
| `t_veh` | 整车：`state`(OFF/ACC_ON/STARTED/FAULT)、`started`、`acc_on`、`rpm/volt`、`fault_word`、`can_silent`、`counts` |
| `t_key` | 键盘：`mask`、`key_code`、`axis[last.. cf..]`、`cmd`、`valid`、`stats(frames/conflict/blocked/reject/timeout)` |
| `t_lift` | 举升：`raw/mv/angle/position`、`state`、`valve out`、`fault`（布尔）、**`fault_raw`**（0=正常/1=开路/2=短路） |
| `t_swing` | 回转：`angle/position/flags/zero/safe/solve_valid`、`state`、`brake`、`dir_pol` |
| `fstat` / `focmode` | FOC 状态与模式（欠压门禁用） |
| `t_param info` | 存储：各组 `rec/left/erase/seq/wr/src` |
| `t_canrx 1` | 打开**真实** CAN 接收帧打印（模拟注入帧永不打印） |

## 4. 已执行用例

### 4.1 M1 / M1b 启车判据

```
t_sim acc off        → [ACC] OFF + ignition key OFF + [VEH] -> OFF + mode 0 + [Swing] Locking...
                      且**无** [UV] snapshot saved
t_sim bus 12500
t_sim acc on         → 500ms 后 ACC_ON，保持 state=1（不 STARTED）
t_sim bus 13000      → 仍 state=1（判据严格大于 13.0V，负例）
t_sim bus 13100      → [VEH] STARTED: volt=13.1V
t_sim bus 12500      → 仍 STARTED（只进不退）
t_sim rpm 600        → [VEH] STARTED: rpm=600, volt=12.5V（转速支路）
t_sim rpm 0          → 仍 STARTED，engine_running 1→0
t_sim acc off        → state=OFF、started=0、acc_on=0
```

结论（2026-11-20）：全部符合，两个计时器独立、门限严格大于、STARTED 锁存、仅 ACC 下电清除。

### 4.2 M2 键盘仲裁

```
t_sim key up hold        → mask=0x001、key_code=UP、cmd U1
t_sim key down hold      → mask=0x003、key_code=UP_DOWN、cmd 全 0、conflict 0→1
t_sim key down release   → mask=0x001、cmd 回 U1（双按变单按立即解除）
t_sim key mid hold       → mask=0x011、key_code=MANUAL_ONEKEY、cmd U1 且 OKm0（手动优先）
t_sim key none           → mask=0x000；300ms 后 valid=0、timeout=1（超时释放）
```

结论（2026-11-20）：全部符合。

### 4.3 M3 举升（`t_seq m3`）

| 输入 | 实测 |
| --- | --- |
| 2203 mV | `0.0 / MIDDLE / IDLE / out=0x00` |
| 3768 mV | `42.9 / UPPER` |
| 1111 mV | `-30.0 / LOWER` |
| 4800 mV | `sensor=1 / FAULT_SENSOR`（角度冻结在上次值，`position=UNKNOWN`） |
| 250 mV | `sensor=1` |
| 4450 mV | `sensor=0 / IDLE`，角度饱和到 `43.0`（线性应为 61.7） |
| `key up hold` | `UP_RUNNING / out=0x01`；松开 → `IDLE / 0x00` |
| `key down hold` | `DOWN_RUNNING / out=0x02` |
| 3768 时按上升 | 不进 `UP_RUNNING`、`out=0x00`（上限拦截生效） |

### 4.4 M4 回转（`t_seq m4`）

| 段 | 实测 |
| --- | --- |
| A `swing 0/2150/-1000` | `ZERO` / `RIGHT_LIMIT` / `LEFT_LIMIT`，flags 对应位正确 |
| B 左转 | `unlocking → unlocked → LEFT_RUNNING/UNLOCKED`；松开 `locking → locked → IDLE` |
| C 左限位按左 | 打印 `[Swing] Left motion forbidden (limit)`、`out` 不动 ✅ **但 `state` 仍 `LEFT_RUNNING`**（D-1） |
| C 右限位按右 | 同上，`state` 残留 `RIGHT_RUNNING` |

### 4.5 M6 阀故障（`t_seq m6`，2026-11-20）

| 注入 | 实测 |
| --- | --- |
| `valve 0 0 0 0` | `IDLE`、`out=0x00`、fault 三项 0 |
| `valve 1 0`（开路） | `FAULT_VALVE`、`out=0x00`、`valve_up=1` |
| `valve 2 0`（短路） | 仍 `FAULT_VALVE`、`out=0x00`；`valve_up` 仍显示布尔 1，原始码见 `fault_raw=2` |
| `valve 0 2`（下降阀） | `FAULT_VALVE`、`valve_down=1`（原始码 2） |
| `valve 0 0`（清除） | **自动回 `IDLE`**、`out=0x00`（无需人工复位） |
| 故障期 + `key up hold` | 仍 `FAULT_VALVE`、`out=0x00`（手动被禁） |
| 清除后 | `IDLE`、`out=0x00` |

结论：置位、输出禁止、手动禁止、自动恢复全部符合。唯一差异是"开路/短路"只能在 `fault_raw` 区分（`t_lift` 已补该行；`valve_up/down` 是 LiftControl 的布尔镜像，不是故障码）。

**复测（同日，含 `fault_raw`）**：`valve 1 0` → `fault_raw up=1`；`valve 2 0` → `fault_raw up=2`；`valve 0 2` → `dn=2`；清除后全部归 0 并回 `IDLE`。开路/短路区分已确认。

### 4.6 M7 机型设置（`t_seq m7`，2026-11-20）

| 注入（协议值） | 内部枚举 `teeth=` | 说明 |
| --- | --- | --- |
| — | `0` | 基线未设置（`TEETH_UNSET`） |
| `1`（13 齿） | **`2`** | `TEETH_13 = 2` |
| `2`（14 齿） | **`3`** | `TEETH_14 = 3` |
| `3`（11 齿） | **`1`** | `TEETH_11 = 1` |
| `3`（重复） | `1` | **同值去重：am `seq` 未增，未写 Flash** |
| `0`（清除） | `0` | `clear_action=0(KEEP)`，无 `teeth cleared` 打印 |

- Flash 写入次数与 `seq` 吻合：三次真实切换后 `am seq=3`，清除后 `seq=4`。
- `t_mech_check` → `PASS`（机型写入不影响机械表）。

> **诊断注意**：`t_param values` 打印的是**内部枚举**，不是协议值。协议 `1/2/3` 分别对应内部 `2/3/1`（`sys_param.h`：`TEETH_UNSET=0 / TEETH_11=1 / TEETH_13=2 / TEETH_14=3`）。这正是 O-01「协议值、用例、代码三者编码不一致」的根源，比对时按上表换算。

## 5. 本轮发现（2026-11-20）

| 编号 | 现象 | 影响 | 处置 |
| --- | --- | --- | --- |
| **D-1** | 限位拦截后状态残留 `LEFT_RUNNING`/`RIGHT_RUNNING`（`swing_actions.c` 的 `enter_*_running` 只 `LOG_WARN` + `return`，跳转表已先迁移） | 诊断误导；P0-11 接通状态帧后 HMI 会误报"电机转动" | 待修：拦截时投停止事件让状态回落 IDLE |
| D-2 | `t_key` 的 `reject` 按**帧**累加（`conflict` 按边沿） | 现场会误读为"按了 N 次" | 待统一为边沿计数 |
| D-3 | 未收过帧时 `t_key` 显示 `rx 90077ms ago`（`rx_tick=0` 假象） | 轻微误导 | 未收帧时显示 `never` |
| D-4 | `t_veh` 的 `fault_ms` 进 FAULT 后继续累加（`4250/2000`） | 无害，仅显示超门限 | 可在进 FAULT 时清零 |
| D-5 | 传感器故障时 `angle` 冻结在上次可信值，只靠 `position=UNKNOWN` 表达无效 | 易把冻结值当实测值 | 文档标注即可 |
| D-6 | `t_seq`/`t_bench` 期间 msh 阻塞（`t_bench` 约 4 s；`m3` 24 s、`m4` 20 s、`m6` 16 s） | 期间不能敲命令 | 属设计，串口超时设长即可 |

**已知缺口（不是新发现，测到属正常）**

- 电机不转：业务层未接 FOC（P0-2）；举升阀只发 0x18FF1D60（无执行器不动）。
- 一键无反应：`seq_control_update()` 无调用者、ONKEY 被跳转表丢弃（P0-5）。
- 传感器故障/恢复**立即**生效，用例要求 2 s（E09）；限位后 5 s 保持未实现（E04）。
- 状态帧多项恒值、灯帧全绿（P0-11 / H14/H15）。

## 6. 结果回传格式

每轮按模块回传：

1. 命令原文（脚本就跑 `t_seq mx`）；
2. 紧随其后的完整打印，保留 `[ ]` 前缀；
3. 现象（刹车是否有声音、阀是否有动作）。

判定口径：`通过` / `不通过（附证据）` / `阻塞（附原因）` / `已知缺口`。
