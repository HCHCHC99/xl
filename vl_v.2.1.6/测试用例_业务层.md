# 测试用例：业务层（模块级 · 台架模拟）

- 适用固件：2026-11-20 及以后（含 `t_sim` / `t_bench` / `t_seq` / `t_canrx` / `t_swing`）；
  2026-11-23 起另含 `obj_base_emit` 槽位修复与 `t_arb` / `t_evt` / `t_sm_dump`
- 目的：在没有钥匙、没有可调电源、没有 CPB 面板、没有 CAN 仪的条件下，验证业务链路
  （判据 → 门禁 → 状态机 → 动作 → 输出 → 反馈）的**判定与状态迁移**。
- 边界：**不验证功率输出**。`t_sim` 只喂"读数"；电机驱动未接业务层（P0-2），
  举升阀只发 CAN 帧。要转电机请用 `focmode` 直控。
- 工具说明见 `任务清单.md` §11；存储/欠压专项见 `测试用例_批次1_2.md`。

## 0. 每轮固定前置

**每次复位/重新烧录后 `t_sim` 全部清零**，必须先跑：

```
t_bench
```

等价于（每步间隔 1 s，最后等 1.2 s）：

```
t_sim key none         # 【P3 新增】先清按键，否则残留按键会让启车 rebaseline 锁死键盘
t_sim cansilent 0      # 无真实 CAN 时必做，否则 2s 后整车 FAULT
t_veh_clr
t_sim bus 13200        # >13.0V
t_sim acc on           # 500ms 去抖
```

通过判据：`[bench] OK: STARTED, ready for test`。
失败会打印 `NOT READY` 并附 `state/started/acc/fault/volt`。

> 踩坑记录：2026-11-20 两次漏掉 `cansilent 0`，都得到 `[VEH] -> FAULT (word=0x1)`。
>
> 踩坑记录（2026-11-23，P3 m11）：`t_bench` 前手工跑过 `t_sim key mid+rear+home`
> 未释放，50 ms 重发保活 mask≠0；ACC 上电时 `kb_request_rebaseline()` 见按键仍按着
> 就进 `KSM_BLOCKED`，而 BLOCKED 只在 mask==0 解除 ⇒ 整轮所有手动键被静默吞掉，
> m11 的"手动打断"会假失败（无 `[Seq] Interrupted`、`[Seq] Abort=0`）。
> 现 `t_bench` 已内置 `t_sim key none`（打印 `[bench] 0/5 release sim keys`）。

> **D-11 之后（2026-11-23）**：`t_bench` 从"建议"变成"硬前置"——一键前置条件现在直接读
> `vehicle_is_started()`。**`m5` / `m11` / `m13` / `m14` / `m18` 不先 `t_bench` 会连续打印
> `[Seq] Precondition fail: not started` 或 `[Calib] reject: not started` 并返回 `-2`/-1**；
> `m15` / `m16` 只用手动，不受影响。

## 4. 已执行用例

### 4.1 M1 / M1b 启车判据

```
t_sim acc off        → [ACC] OFF + ignition key OFF + [VEH] -> OFF + mode 0 + [Swing] Locking...
                      且**无** [UV] snapshot saved
t_sim bus 12500
t_sim acc on         → 500ms 后 ACC_ON，保持 state=1（不 STARTED）
t_sim bus 13000      → 仍 state=1（判据严格大于 13.0V，负例）
t_sim bus 13100      → [VEH] STARTED: volt=13.1V
t_sim bus 12500      → 仍 STARTED（只进不退）
t_sim rpm 600        → [VEH] STARTED: rpm=600, volt=12.5V（转速支路）
t_sim rpm 0          → 仍 STARTED，engine_running 1→0
t_sim acc off        → state=OFF、started=0、acc_on=0
```

结论（2026-11-20）：全部符合，两个计时器独立、门限严格大于、STARTED 锁存、仅 ACC 下电清除。

### 4.2 M2 键盘仲裁

```
t_sim key up hold        → mask=0x001、key_code=UP、cmd U1
t_sim key down hold      → mask=0x003、key_code=UP_DOWN、cmd 全 0、conflict 0→1
t_sim key down release   → mask=0x001、cmd 回 U1（双按变单按立即解除）
t_sim key mid hold       → mask=0x011、key_code=MANUAL_ONEKEY、cmd U1 且 OKm0（手动优先）
t_sim key none           → mask=0x000；300ms 后 valid=0、timeout=1（超时释放）
```

结论（2026-11-20）：全部符合。

### 4.3 M3 举升（`t_seq m3`，18 步 · ✅ 2026-11-23 复测通过）

> **脚本结构（P5 起）**：传感器阈值 + 2 s 确认整段已移入 `m8`（§4.12）——2 s 确认与
> 1 s 步长不兼容，旧脚本"注入后下一拍必报"的断言不再成立。`m3` 现在只测三件事：
> **角度映射 / 手动阀输出 / 上限拦截**。

| 步 | 输入 | 实测 |
| --- | --- | --- |
| 1–2 | 2203 mV | `raw=1367`、`0.0° / MIDDLE / IDLE / out=0x00` |
| 3–4 | 3768 mV | `raw=2338`、`42.9° / UPPER(+43.0°)` |
| 5–6 | 1111 mV | `raw=689`、`-30.0° / LOWER(-30.0°)` |
| 7–9 | 2203 + `key up hold` | `UP_RUNNING / out=0x01` |
| 10–11 | `key up release` | `IDLE / out=0x00` |
| 12–13 | `key down hold` | `DOWN_RUNNING / out=0x02` |
| 15–17 | 3768 + `key up hold` | `[Lift] Up refused: already at upper limit` → `IDLE / out=0x00`（P6 拦截） |

结论：三点线性（1367/2338/689 ↔ 0.0/+42.9/−30.0）、手动起停、上限拦截全部符合。

两条判读注意：

- 全程 `sens: latched=0 timing=0`、`fault: sensor=0`，说明 2203/3768/1111 都在迟滞带内，
  未误触 2 s 确认。
- 步 16 的 `[Lift] Up refused` 打印在 `[sim] key up hold` **之前**是正常的：`t_sim`
  先注入、后打 `[sim]` 行（`input_sim.c` 的调用顺序），被触发模块的打印自然排在前。
  反过来，`[VFB] confirmed` 出现在 `[sim]` **之后**是因为它晚了 500 ms 去抖。

未覆盖：**下限处按下降**（`[Lift] Down refused`）没有断言，代码与上升分支对称、风险低；
要补就手敲 `t_sim lift 1111` → `t_sim key down hold` → `t_lift`，别改 `m3` 的步数。

### 4.4 M4 回转（`t_seq m4`，20 步 · ✅ 2026-11-23 复测通过）

| 段 | 步 | 实测 |
| --- | --- | --- |
| A 角度映射 | 1–6 | `0→ZERO(zero=1)`、`2150→RIGHT_LIMIT`、`-1000→LEFT_LIMIT`，flags 对应位正确 |
| B 0° 起步左转 | 7–12 | `unlocking → unlocked → LEFT_RUNNING / UNLOCKED`；+1 s 仍 `LEFT_RUNNING`；松开 `locking → locked → IDLE` |
| C 左限位按左 | 13–15 | `[Swing] Left motion forbidden (limit)` → 立即 `locking → locked`，`state=IDLE`、`out` 不动 |
| C 右限位按右 | 17–19 | `[Swing] Right motion forbidden (limit)` → 同样回 `IDLE / LOCKED` |

结论：A/B/C 全过。两条 P6 修复的现场证据：

1. **0° 起步不再被过零停拦住**（步 8）：`swing_crossed_zero()` 改为严格跨侧后，
   `prev=0 → now=0` 不算跨越，可以从零位出发。
2. **限位拦截不再残留 RUNNING**（D-1，步 14/18）：拦截分支同步投"松手"，
   `LEFT_RUNNING → LOCKING → IDLE`、抱闸锁死。2026-11-20 旧记录此处 `state` 残留
   `LEFT_RUNNING`，现已修复。

未覆盖：方向直接反切时的 `Unlocking (dir=N)` 打印滞后（D-9）——本轮两段都是
`key none → 单向 hold`，`pending_dir` 已归零，D-9 不显现。

### 4.5 M6 阀故障（`t_seq m6`，2026-11-20）

| 注入 | 实测 |
| --- | --- |
| `valve 0 0 0 0` | `IDLE`、`out=0x00`、fault 三项 0 |
| `valve 1 0`（开路） | `FAULT_VALVE`、`out=0x00`、`valve_up=1` |
| `valve 2 0`（短路） | 仍 `FAULT_VALVE`、`out=0x00`；`valve_up` 仍显示布尔 1，原始码见 `fault_raw=2` |
| `valve 0 2`（下降阀） | `FAULT_VALVE`、`valve_down=1`（原始码 2） |
| `valve 0 0`（清除） | **自动回 `IDLE`**、`out=0x00`（无需人工复位） |
| 故障期 + `key up hold` | 仍 `FAULT_VALVE`、`out=0x00`（手动被禁） |
| 清除后 | `IDLE`、`out=0x00` |

结论：置位、输出禁止、手动禁止、自动恢复全部符合。唯一差异是"开路/短路"只能在 `fault_raw` 区分（`t_lift` 已补该行；`valve_up/down` 是 LiftControl 的布尔镜像，不是故障码）。

**复测（同日，含 `fault_raw`）**：`valve 1 0` → `fault_raw up=1`；`valve 2 0` → `fault_raw up=2`；`valve 0 2` → `dn=2`；清除后全部归 0 并回 `IDLE`。开路/短路区分已确认。

**复测（2026-11-23，P4 去抖在环，16 步 · ✅ 通过）**

| 步 | 注入 | 实测 |
| --- | --- | --- |
| 1–2 | `valve 0 0 0 0` | `IDLE`、`out=0x00`、`fault_raw up=0 dn=0` |
| 3–4 | `valve 1 0`（开路） | `[VFB] up valve fault confirmed`（500 ms 后）→ `FAULT_VALVE`、`valve_up=1`、`raw up=1` |
| 5–6 | `valve 2 0`（换短路） | **仍 `FAULT_VALVE`，无第二次 confirmed**；`valve_up=1`（锁存的首次码）、`raw up=2` |
| 7–8 | `valve 0 2`（下降阀短路） | `[VFB] down valve fault confirmed`；up 因 `raw=0` 已恢复 → `valve_up=0 / valve_down=1 / raw dn=2` |
| 9–10 | `valve 0 0` | `[VFB] valve fault cleared` → `IDLE` |
| 11–13 | `valve 1 0` + `key up hold` | `FAULT_VALVE`、`out=0x00`（故障期禁手动） |
| 14–16 | `key none` + `valve 0 0` | `[VFB] valve fault cleared` → `IDLE` |

新增判据：**锁存期内原始码变化不重投、不刷新**（步 5–6）。`valve_up` 镜像是
"首次确认时的码是否非 0"，`fault_raw` 才是当前码——两者对不上是设计，不是错位。

### 4.6 M7 机型设置（`t_seq m7`，2026-11-20）

### 4.16 M23 编码器故障真实上报（P9a，✅ 2026-11-23 通过）

> 脚本 `m19`（21 步）。这是 `业务.md` §13.8.6 第 4 项"补 `encoder_fault` 生产者"。
> **不新增 msh**：用现成的 `t_sim clear swing` 关掉台架模拟，让解算回到真实路径
> （台架上无绝对编码器 ⇒ 无效），天然模拟"编码器断线"。

**为什么这条以前测不到**

旧实装里 `SWING_EVT_ENCODER_FAULT` 只驱动状态机（进 FAULT、停电机），
**没有写 `ctx.encoder_fault`**。所以：
- `t_sta` 的 `enc` 位恒 0、灯不红；
- 一键前置条件第 4 条是死的；
- 一键会启动但 `SWING_EVT_SEQ_*` 在 FAULT 态无跳转 → 筒不动、空跑超时。

**判据**

| 步 | 命令 | 期望 |
|---|---|---|
| 3 | `t_swing` | 初始 `IDLE`、`enc_rep=0` |
| 5 | `t_swing`（`t_sim swing 600` 后） | `angle=60.0°`、`position=MIDDLE`、`enc_rep=0` |
| 6 | `t_sta` | `B1 enc=0` |
| 7 | `t_sim clear swing` | `[Swing] angle solve INVALID, report encoder fault` → `[Swing] encoder_fault -> 1` → `[Swing] Enter FAULT state` |
| 8 | `t_swing` | `position=UNKNOWN`、`enc_rep=1`、`state=IDLE/FAULT`（角度保留最后可信值 60.0） |
| 9 | `t_sta` | `B1 enc=1` |
| 10 | `t_led` | `left/right/motor = 0xC red-blink <- encoder fault` |
| 11 | `t_seq_run mid` | `[Seq] Precondition fail: encoder fault` → `-2` |
| 12–13 | `t_sim swing 600` + `t_swing` | `[Swing] angle solve recovered, encoder fault cleared`；`encoder_fault -> 0`；`state=IDLE`、`enc_rep=0` |
| 14–15 | `t_sta` / `t_led` | `enc=0`；灯回绿 |
| 16–18 | 再次失效 + `key left hold` + `t_swing` | `LEFT_RUNNING`（Q30-a：故障中手动仍可动） |
| 20 | `t_sim swing 600` | 恢复，故障清除 |

**实测（2026-11-23，`t_seq m19` 21 步，通过）**

| 步 | 实测 |
|---|---|
| 3 | `position=UNKNOWN / solve_valid=0 / enc_rep=0`，**未报故障**（上电即无效，无跳变） |
| 4–6 | `60.0° / MIDDLE / solve_valid=1`；`B5-6=0x0168=360`、`B1 enc=0` |
| 7 | `[sim] swing -> real input` → `angle solve INVALID, report encoder fault` → `encoder_fault -> 1` → `Enter FAULT state` |
| 8–9 | `angle=60.0`（保留最后可信值）/ `position=UNKNOWN` / `enc_rep=1`；`B1 enc=1`、`swing_st=5` |
| 10 | 灯 `11 CC 21 11 11 00 2C 11`：left/right=`0xC`、motor=`0xC` |
| 11 | `Precondition fail: encoder fault` → `-2` |
| 12–13 | `encoder_fault -> 0` → `angle solve recovered, encoder fault cleared`；`state=IDLE` |
| 14–15 | `B1 enc=0`；灯全绿 |
| 16–18 | 再次失效 → `FAULT`；`key left hold` → `LEFT_RUNNING / brake UNLOCKED`（Q30-a） |
| 19–21 | 松手 `Locking` → 恢复 → `enc_rep=0` |

**结论：M23 通过（P9a 关闭）。** 三条判读经验：① 步骤 3 证明"上电即无效不报"的边界生效；
② 恢复打印顺序为 `encoder_fault -> 0` 在前、`recovered` 在后，对应"先清标志再投事件"；
③ C 段在 FAULT 态恢复（CLEAR 生效）、D 段在 IDLE 态恢复（CLEAR 被忽略），两条路径都覆盖到。

**已知边界**

- **上电即断线不报**：`position`/`last_position` 初值都是 `UNKNOWN`，没有"有效→无效"
  的跳变可判。方案 3 下这正好避免台架误报；真机"上电即断线"由方案 1 的 SPI
  看门狗负责（判从机应答，不依赖跳变）。启用 SPI 时见 `业务.md` §13.8.7。
- `t_encfault 1` 与真实路径共用一个字段：真实路径恢复时会把注入的值清掉。
  台架上先 `t_encfault 1` 再 `t_sim clear` → `t_sim swing` 会看到它被清零，属预期。
- 进 FAULT 时若正按着方向键，`FAULT → LEFT_DOWN` 有跳转，会立刻重新解锁运行
  （Q30-a 的必然结果）。台架上看到 `FAULT → UNLOCKING → LEFT_RUNNING` 连续三行不是抖动。

### 4.17 M24 一键前置条件读实时启车状态（D-11，✅ 2026-11-23 台架通过）

> **手动用例，不编脚本号**——避免又一次步数基线漂移（`m3` 24→18 的教训）。
> 目的：证明"钥匙清故障后整车停在 `ACC_ON`"时，一键**不再**启动。

**背景**：`seq_check_precondition()` 原来读 `ctx->vehicle_started`（事件副本）。它只在

修法：直接读 `vehicle_is_started()`（`业务.md` §15.15）。

**前置**：`t_encfault 0` → `t_bench`（STARTED）→ `t_seq_auto 0` → `t_sim swing -500` → `t_sim lift 2203`。

### 4.18 M25 零点校准状态机（P9/B-10，选项 A，✅ 2026-11-23 台架通过）

> 脚本 `m18`（29 步，约 29 s，**前面必须 `t_bench`**）。
> 零点口径＝选项 A（`业务.md` §13.9 / §15.16）：校准 = 两点式对齐
> `FOC_PROC_ENC_ALIGN` + `is_calibrated=1` + 快区立即落盘（`tube_x10=0`、`valid=0x03`）
> + 筒角置 0。**B15（对齐结果立即落盘）随本批关闭。**

**新增命令（`t_calib`）**

```
t_calib               # 状态总览：state/count/calibrated/aligned/reason/fast
t_calib start         # 直接进 EXEC（前置条件照常检查）
t_calib abort         # 强制回 IDLE
t_calib count         # 本上电周期已用次数
t_calib sim dbl       # 注入双击（IDLE → PREP）
t_calib sim click     # 注入按下（PREP → ARMED）
t_calib sim up        # 注入松开（ARMED <2s → FAIL）
t_calib sim long      # 注入长按 2s（ARMED → EXEC）
```

**状态流**

```
IDLE --双击--> PREP(黄5s) --5s内再按(按住)--> ARMED(绿5Hz闪)
ARMED --长按>=2s--> EXEC --成功--> DONE(绿2s) --> IDLE
                   --失败--> FAIL(红2s) --> IDLE
ARMED --<2s 松开--> FAIL；PREP --5s 超时--> IDLE（不消耗次数）
```

前置条件（任一不满足 → 拒绝 + 红灯 2 s）：次数 ≥2 / 未启车 / 编码器·传感器·阀故障 /
手动按键 / **一键运行中（不打断一键）** / FOC 忙。次数按"进入 EXEC"计，每上电周期 2 次。

**`t_seq m18` 判据（29 步）**
