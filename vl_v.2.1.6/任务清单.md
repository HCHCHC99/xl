## 1. 项目定位与角色边界

本工程是 **UTMotVCU，卸粮筒水平回转无刷电机控制器**。它同时负责向 RGV 电磁阀盒请求升降阀，但不直接驱动升降执行机构。

| 节点 | 职责 | 是否属于本工程 |
| --- | --- | --- |
| CPB 遥控器（8/10 键） | 发按键、显示按键灯与状态灯 | 否；本工程只收 `0x18FF8380`、发 `0x18FFA4F0` |
| HMI 显示屏 | 显示状态、下发机型 | 否；本工程只发 `0x18FF11D1`、收 `0x18FF7F18` |
| RGV 电磁阀盒 | 驱动升降阀、反馈阀故障/通道 | 否；本工程发 `0x18FF1D60`、收 `0x18FF0E63` |
| 卸粮离合 VCU（选配） | 离合电机控制、`0x18FF10D5`、`0x18FFA5F0` | 否；本工程只做离合按键仲裁 |
| 发动机 ECU | 提供转速 | 否；本工程收 `0x0CF00400` |
| **UTMotVCU（本工程）** | 水平回转 FOC、升降阀请求、一键、校准、灯、故障、存储 | **是** |

报文与信号定义见 `xl.xlsx` 的 `01_报文清单` 和 `02_信号定义`；代码中的唯一定义源是 `applications/CAN/protocol_defs.h`。

## 2. 主要业务逻辑

### 2.1 物理对象与坐标

| 量 | 定义 |
| --- | --- |
| 回转零位 | 0°，容差 ±0.5° |
| 回转左/右限位 | −100°±2° / +215°±2°；软件电子限位再外扩 1°，即 −101° / +216° |
| 回转方向 | 筒左转 = 角度减小 = 电机右转；筒右转 = 角度增大 = 电机左转 |
| 举升零点 | 2203 mV，36.4 mV/° |
| 举升限位 | +43°±2° / −30°±2°，传感器量程 500～4500 mV |
| 一键目标 | 右中 +120°、右后 +215°、回位 0°；起转高度 +25°，终点高度 +34° |
| 回转传动 | 电机内部减速比 × 机型外部齿比；默认 216 × 65/13 = 1080 |

### 2.2 数据流

```
CPB 0x18FF8380 ──► keyboard_sm ──► 事件 ──► app_main 门禁/路由
                                             │
                    ┌────────────────────────┴───────────────────────┐
                    ▼                                                ▼
             SwingControl                                      LiftControl
        （手动/一键/刹车/限位）                            （上升/下降/限位/故障）
                    │                                                │
                    ▼                                                ▼
              motor_t（旧对象）                              0x18FF1D60 → RGV
                    │                                                │
                    ▼                                                ▼
             FOC 模式/环路（当前未接）                        0x18FF0E63 ← RGV
                    │
                    ▼
        TMR4_3 PWM → 回转无刷电机 + ABZ 编码器
```

反馈方向：

```
传感器/状态机 ──► status_tx ──► 0x18FF11D1 → HMI
            └──► led_tx    ──► 0x18FFA4F0 → CPB
```

### 2.3 门禁与优先级

1. **ACC 上电门（门 1）**：钥匙下电确认后拒绝所有“动作开始”，不拦停止。
2. **启车门（门 2）**：一键、离合要求已启车；手动四向只要求 ACC。
3. **启车判据**：转速 >400 rpm 或电压 >13.0 V，各自独立连续 500 ms，任一满足即 STARTED；本上电周期保持，仅钥匙下电清除。
4. **启车重按**：进入 STARTED 时若按键仍按住，锁死到全部松开，必须重按。
5. **同轴互斥**：左+右、上+下同时按下无输出；松开一个后剩下方向生效。
6. **手动优先**：手动键存在时一键不响应。
7. **一键互斥**：同一键重复按忽略；其他一键或手动键立即中断并执行新动作。
8. **离合优先**：离合动作时停回转、禁一键；回转/一键中触发离合立即停止。
9. **故障降级**：一键停、手动尽量保留；传感器故障时只保留允许的手动。
10. **安全停止**：钥匙下电、欠压、堵转、过流均应立即停止输出。

### 2.4 一键时序

`xl.xlsx` 定义的是**串行**流程：

```
右中：升到 +25° → 右/左转到 +120° → 升到 +34° → 关上升阀
右后：升到 +25° → 右/左转到 +215° → 升到 +34° → 关上升阀
回位：升到 +25° → 转到 0° → 升到 +34° → 下降到 0° → 保持 2 s → 关阀
```

旧用例还要求按起点高度分流：>+34° 直接转、+25～+34° 边转边升、<+25° 先升到 +25°。当前 `seq_config.c` 的顺序与 `xl.xlsx` 一致；若后续要兼容旧用例的“边转边升”，需要增加并行步骤。

## 4. FOC 架构重构与业务接入

### 4.1 现状判断

FOC 核心已经是一套**可独立运行、由 msh 驱动的子系统**：能采样、能测角、能跑电流/速度/位置环、能对齐编码器、能输出 VOFA。问题是它与业务层之间没有桥：

- 业务层仍使用旧 `motor_t`，`drv_ops/fb_ops/ctrl_ops` 全为 NULL（`motor_config.c:84-87`）。
- `motor_start()` 只调 `ctrl_ops->set_target`，NULL 时直接返回（`motor.c:110-123`）。
- `motor_stop()` 同样为空（`motor.c:125-133`）。
- `bg_modules.c` 在 FOC 接管 PWM 时跳过 `motor_update()`（`bg_modules.c:63-70`）。
- `Foc_Mode_PwmOwned()` 在 `FOC_DISABLE_LEGACY_6STEP=1` 时恒为 1（`foc_mode.c:390-397`）。
- 业务角度 getter 仍指向 `motor->current_position`，该字段唯一写入点已被注释（`swing_init.c:22-44`）。

结论：**不能只把 `motor_start` 改成调 FOC**。需要一层明确的适配层，否则会把“刹车、限位、零位、方向、单位、停机时序”这些业务语义散落到 FOC 模式代码里。

### 4.2 三种方案对比

| 方案 | 做法 | 优点 | 缺点 | 建议 |
| --- | --- | --- | --- | --- |
| A. 填旧 `motor_t` ops | 用 FOC 实现 `drv_ops/ctrl_ops` | 业务代码改动小 | `motor_t` 的 API 是“方向+占空比”，不足以表达位置/速度/状态；容易把 FOC 塞进旧模型 | 不推荐 |
| B. 新建 `swing_axis` 适配层 | 业务状态机 → `swing_axis` → FOC | 单位、方向、零位、限位、刹车、停机时序集中一处；FOC 保持独立 | 需要新增文件并改 `swing_actions`/`seq_actions` | **推荐** |
| C. 业务直接调 FOC | `swing_actions` 直接 `Foc_Mode_SetMode` | 最少代码 | 业务层被 FOC 量纲污染；刹车/限位/零位难复用 | 不推荐 |

### 4.3 推荐分层

```
L4 业务状态机      SwingControl / LiftControl / SeqEngine
                         │  逻辑事件、目标角、方向
                         ▼
L3.5 swing_axis    applications/swing/swing_axis.c/.h
    - 模式仲裁：手动速度 / 一键位置 / 停止
    - 单位换算：筒 0.1° ↔ 电机 rev；方向；i_total
    - 零位/回零/绝对参考合法性
    - 限位/过零/到位/故障回读
    - 刹车解锁/锁止时序
                         │
                         ▼
L3 FOC 核心        foc_mode / foc_control / current/speed/position loop
                         │
                         ▼
L2 硬件            hw_encoder / hw_tmr4_pwm / bsp_adc_foc
```

`motor_t` 建议降级为“状态镜像/兼容层”，不再承担驱动；`stall`、`param_store` 等旧消费者改为查询 `swing_axis` 或 FOC 模式。

### 4.4 适配层 API 建议

```c
/* 初始化/使能 */
int  swing_axis_init(void);
int  swing_axis_enable(void);

/* 手动点动：dir = +1 角度增大（筒右转），-1 角度减小（筒左转） */
int  swing_axis_jog(int8_t dir);
int  swing_axis_move_to(int32_t angle_x10);   /* 一键位置目标，0.1° */

/* 停止：先减速到 0，再 IDLE + 抱闸；由状态机轮询 stopped */
int  swing_axis_stop(void);
uint8_t swing_axis_is_stopped(void);

/* 零点/参考 */
int  swing_axis_set_zero(int32_t raw_count);
uint8_t swing_axis_reference_valid(void);

/* 反馈 */
int32_t swing_axis_get_angle_x10(void);
int32_t swing_axis_get_speed_rpm(void);
uint8_t swing_axis_in_position(void);
uint8_t swing_axis_get_fault(void);

/* 周期任务（50 ms） */
void swing_axis_tick_50ms(void);
```

关键语义：

- `jog` 内部用速度模式：`g_spd_target_rpm = sign × JOG_RPM`，`Foc_Mode_SetMode(FOC_MODE_SPEED)`；松手后先 `g_spd_target_rpm = 0`，等 `|rpm| < 阈值` 再 `FOC_MODE_IDLE`，最后允许抱闸。
- `move_to` 内部用位置模式：`g_pos_target_rev = angle_to_motor_rev(target)`，`Foc_Mode_SetMode(FOC_MODE_POSITION)`；到位判据用 `g_pos_in_pos` + `SWING_NEAR` 双保险。
- `stop` 不允许在 20 kHz ISR 内调用；由 50 ms tick 或事件线程执行。
- 刹车时序必须由适配层控制：**先停 PWM/减速，再抱闸**；当前 `swing_act_enter_locking` 立即 `motor_stop + hw_brake_lock`，在 FOC 下需要改成“请求停止 → 等 stopped → 抱闸”。

### 4.5 单位与方向换算

设 `i_total_x100 = mech_rt.i_total_x100`，`CPR = 4096`，编码器计数为电机轴累计计数：

```
motor_rev   = count / CPR
tube_deg    = motor_rev * 360 / i_total
angle_x10   = count * 360000 / (CPR * i_total_x100)
motor_rev   = angle_x10 * i_total_x100 / 360000
```

默认 `i_total = 216 × 65/13 = 1080`：

- 筒 1° ≈ 电机 3 圈（1080/360）。
- 筒 2.4 r/min ≈ 电机 2592 rpm；实际点动转速应按机械能力配置，不能直接套用例里的 2.4 r/min。
- 方向必须只在一个地方取反。建议 `swing_axis` 里保留一个 `s_dir_sign`，在台架做一次极性识别（按右转，角度应增大；否则翻转该符号），不要在 FOC、mech、业务三处各翻一次。
- `mech_cfg` 默认 `pole_pairs=4` 是旧机械表遗留值；FOC 使用 `CFG_MOTOR_POLE_PAIRS=10`。角度换算不使用极对数，但应把 mech 的极对数改成 10 或明确标注它只用于旧解算，避免误用。

### 4.6 绝对角问题（最关键）

ABZ 是增量编码器，`hw_encoder_init()` 把 `s_count` 清 0（`hw_encoder.c:167-183`）。上电时卸粮筒可能停在任意位置，因此：

- **无法直接得到筒的绝对角度**；
- 零位、左右限位、一键目标都无法判定；
- 现有 `swing_angle_is_solve_valid()` 又依赖三颗 SPI 编码器的 `abs_angle` 解算，当前 `BSP_USING_ABS_ENCODER=1` 时 `abs_angle` 未初始化，返回 UNINIT，`swing_angle_update()` 会直接返回（`swing_angle.c:227-251`）。

可选路线：

| 路线 | 做法 | 代价 | 适用 |
| --- | --- | --- | --- |
| 1. 恢复绝对编码器 | 在输出轴装 KTH7812/SPI 绝对编码器，快区存“绝对原始值—电角度” | 需要驱动、引脚重新分配、快区联动 | 精度最好，与原设计一致 |
| 2. ABZ + 上电找零 | 上电慢速向一侧限位/零位开关移动，建立参考 | 需要额外动作、可能被物料阻挡；一键前必须有参考 | 无绝对编码器时的兜底 |
| 3. 掉电前位置存档 + 假设未移动 | 快区存最后位置，上电读回 | 断电期间筒可能被移动，安全性不足 | 只能做辅助校验 |

**建议先做决策再改代码**。如果短期必须让一键跑起来，至少要实现路线 2 的“上电找零”，并在找到参考前把 `calib_sta` 置未校准、一键禁止。

> **2026-11-20 决策（取代上面的待决策）**：采用**路线 3 的变体**——掉电前把筒角与 offset 指纹写快区，上电用「一点式对齐重建电角度 + 指纹一致性校验」恢复筒角；前提是**理想机械自锁**（掉电后机械不会动）。不做上电找零，不启用 SPI 绝对编码器。触发点为**欠压 11 V / 30 ms**（ACC 下电只急停不存档）。完整方案与固有限制（指纹对 1/3° 整数倍位移是盲区）见 `业务.md` §13。

### 4.8 建议实施顺序

不要先改 FOC 核心。按“先读、再动、再闭环、最后补安全”的顺序做：

1. **只读接入**：新增 `swing_axis`，先只做 `get_angle_x10()` 和 `reference_valid()`，用 `t_abz` + 手转电机核对换算和方向；此时不动 PWM。
2. **手动速度环**：实现 `jog()`，把 `swing_actions.c` 的 `swing_motor_start/stop` 改为适配层调用；增加“停稳后再抱闸”的等待。
3. **一键位置环**：实现 `move_to()`，先用 msh/临时命令验证 +120°、+215°、0° 三个目标，再接 `SEQ_ACT_SWING_MOVE_TO`。
4. **角度链路收口**：把 `swing_encoder_getter` 换成 `swing_axis_get_angle_x10`，把 `swing_angle_is_solve_valid()` 改为查询适配层参考有效；验证限位/零位事件。
5. **一键链路收口**：键盘传真实一键位、app_main 50 ms 调 `seq_control_update()`、修 `seq_control_update_onekey` 的重复/中断语义、修回位 2 s 保持。
6. **安全与反馈**：ACC 下电停止、堵转接 FOC、参数保存互锁、状态帧/灯帧接真实源。

每一步都可以单独上板验证，避免“FOC 算法 + 业务语义 + 单位换算”同时改动导致问题难以定位。

## 10. 当前实施焦点：绝对角 + 欠压（2026-11-20 定稿）

> 本节是**唯一执行入口**（做什么、按什么顺序、每批验收什么）。
> 方案与理由见 `业务.md` §13；FOC 结构改造见 `foc结构优化.md`；历史决策过程见 §4.6、§6-1。

### 10.1 决策摘要

| 项 | 结论 |
| --- | --- |
| 编码器 | 只保留 ABZ（4096 CPR、10 对极）；SPI 绝对编码器代码保留、**不启用** |
| 减速比 | **1080**（电机→筒，216 × 65/13）；`tube_deg = count / 4096 / 1080 × 360` |
| 前提假设 | **理想机械自锁**：掉电后机械不动，筒角与电角度保持不变 |
| 电角度 | 每次"停止 → 向量环"时做 α 一点式对齐（1.3 V / 200 ms）重建 offset；**不判失败** |
| 两点式 | mode 3 保留；成功后写 offset/dir 到快区，并把**筒角置 0** |
| 筒角 | 跨上电由快区快照恢复；用 offset 指纹（**±5 counts**）校验，不一致则作废、要求重新两点式 |

| 欠压门禁 | msh 可用；FOC 转动类操作（IF/CURRENT/SPEED/POSITION、mode 3/5/6/7、一点式对齐）一律拒绝 |
| 参数 | 5 个 UV 参数进 SYSTEM 慢区，默认值用宏；首次烧录/全擦才用宏值 |

```c
static void app_emergency_stop(void)
{
    /* 1. 回转：FOC 回 IDLE（全低 + 抱闸），再复用动作层停电机/锁止 */
```

## 11. 台架输入模拟层（t_sim，2026-11-20 新增）

> **背景**：业务调试依赖 9 类外部输入，而现有 msh 几乎全是"看"的（`t_veh`/`t_key`/`t_lift`/`t_abz`/`fstat`），没有"给"的入口。除刹车（本身是执行器，已有 `t_brake_unlock/lock/state`）外，其余输入在台架上只能靠真实硬件，导致一键、门禁、欠压、阀故障等链路没法脱离现场调试。
>
> **做法**：新增统一模拟层 `applications/service/input_sim.c/.h` + 6 处 getter 钩子，一个 `t_sim` 命令覆盖全部输入。**只替换"读数"，不绕过门禁/状态机/限位/去抖**，所以测出来的行为与真实输入一致。

### 11.2 命令语义

| 命令 | 说明 |
| --- | --- |
| `t_sim` | 列出全部输入：名字 / 是否覆盖 / 当前值 |

| `t_sim valve <up_f> <dn_f> [up_o] [dn_o]` | 0=正常 / 1=开路 / 2=短路；open 为 0/1 开关反馈 |

### 11.4 约束（务必知道）

1. **不绕过任何业务判定**：ACC 仍等 500 ms 去抖，欠压仍要 confirm 30 ms 且已过 200 ms 消隐，限位/门禁/状态机全部照跑。
2. **周期帧必须重发**：面板帧由 50 ms 软定时器重发（否则 300 ms 超时判松手），转速帧同理（100 ms 超时归零）。定时器在首次 `t_sim` 时懒创建。
3. **阀/机型帧只注入一次**；`t_sim teeth` 会写一次 Flash，别在循环里反复发。
4. **`t_sim swing` 会强制解算有效**：这是为了让 MARK-13 未修复时也能调业务。真实编码器链路修好后，应把 `SWING_ANGLE_SIM_ENABLE` 置 0 再回归，避免掩盖真实故障。
5. 打印全部 ASCII/整数（RTT 控制台限制）。
6. **注入不产生 CAN 心跳**：`can_sim_inject()` 直接调回调，不经过解析线程，所以台架上没有真实报文时 `can_is_bus_silent()` 仍判静默 → 500 ms 后 `fault_word` bit0、2 s 后整车 FAULT。**台架无总线时先 `t_sim cansilent 0`**（它把该判定强制为"通信正常"）。
7. **量产/交付前**：`INPUT_SIM_ENABLE` 置 0（与 `SYS_CAP_TEMP_ALLOW_PARAM_WRITE` 同批处理），整层不参与编译，`t_sim` 命令随之消失。
8. **每次复位/重新烧录后所有模拟值清零**（纯 RAM，不落盘）。所以每次上电都要重跑前置，否则 `can_silent=1` 会在 2 s 后把整车打进 FAULT。前置已合成一条命令（每步间隔 1 s，最后等 1.2 s 再给结论，全程约 4 s，期间 msh 阻塞属正常）：

   ```
   t_bench            # 等价于下面四步，bus 默认 13200；t_bench 12500 可指定
   #   t_sim cansilent 0
   #   t_veh_clr
   #   t_sim bus 13200
   #   t_sim acc on
   ```

   成功打印 `[bench] OK: STARTED, ready for test`；失败打印 `NOT READY` 并带 `state/started/acc/fault/volt` 汇总。
   **本坑已实测踩中两次**（2026-11-20）：漏掉 `t_sim cansilent 0` → `[VEH] -> FAULT (word=0x1)`。

**⚠ 本机语法检查必须带这两个 flag**（2026-11-23 踩坑）：

```
gcc -m32 -fsyntax-only -Werror=implicit-function-declaration \
    -Werror=incompatible-pointer-types -I. -Iapplications ... <file.c>
```

原因：`lift_actions.c` 用了 `LOG_WARN` 但没 include `log/log_color.h`，
裸 `-fsyntax-only` 只给一条 warning 就放过，链到 ARM 时变成
`undefined reference to LOG_WARN` 才暴露。加上 `-Werror=implicit-function-declaration`
能在本机就拦住这类"漏 include"。

**⚠ RTT 日志可能出现两段 boot**（2026-11-23 现象）：

烧录后复位、或 RTT 中途重连时，粘贴出来的日志会出现两次 `[BOOT] [n/34]`。
**判据：以含 `[BOOT] === boot done` 的那一段为准**，它后面的 msh 输出才是当前会话。
区分两次 boot 的快法：第一次通常有 `[CFG] no valid key record, using defaults` + `defaults written to flash`，
第二次是 `[CFG] key params loaded from flash`。不是固件重复启动的 bug，不用查。

**⚠ 日志禁用浮点格式**（2026-11-23 踩坑）：

`rt_kprintf` / `LOG_*` **不解析 `%f / %e / %g`**。写了 `%.1f` 会：
① 把 `%.1f` 原样打出来；② 吃掉一个参数位，导致后面的 `%d` 读到错位值。

实例：`"[Seq] home: swing at %.1f deg (within +-%d deg)"` 实测输出
`swing at %f deg (within +-0 deg)`——角度没打出来，`+-2` 还变成了 `+-0`。

需要小数就按 0.1°/0.01 单位拆成"整数位.小数位"自己拼，或统一打印整数单位
（如 `x10=1200`）。**代码评审时 grep 一遍 `%f`。**

**⚠ `t_sim` 的 `[sim]` 行打印在注入之后**（2026-11-23）：

被触发模块的打印出现在 `[sim] ...` **之前**是正常的，不要当成"上一条命令的残留"。
实例：`m3` 步 16 的顺序是

    [Lift] Up refused: already at upper limit
    [sim] key up hold, mask=0x0001

因为 `t_sim` 先 `input_sim_set()` 注入、再 `rt_kprintf` 打 `[sim]` 行。
反过来 `[VFB] ... confirmed` 出现在 `[sim]` **之后**，是因为它晚了 500 ms 去抖——
**打印顺序本身就是"有没有去抖"的标志**。

**⚠ `t_param values` 的 `teeth=` 是内部枚举，不是协议值**（2026-11-23）：

协议 `1/2/3`（13/14/11 齿）↔ 内部 `2/3/1`（`TEETH_UNSET=0 / TEETH_11=1 / TEETH_13=2 / TEETH_14=3`）。
`t_sim teeth 3` 之后看到 `teeth=1` 不是回绕越界，是 `TEETH_11`。详见 `测试用例_业务层.md` §4.6。

**⚠ `m7` 每轮写 4 次 Flash**：`angle_mech` 扇区只有 107 个记录槽，3 次切换 + 1 次清除各占一槽
（用 `seq / left` 对账：基线 `seq=0 left=106` → 切换后 `seq=3 left=103` → 清除后 `seq=4 left=102`）。
反复跑 `m7` 会提前触发擦除；只想验换算用 `t_sim teeth N` + `t_param values` 两步即可。

**⚠ `m3` 自 P5 起是 18 步，不含传感器阈值**：4800/250/4450 mV 那几行已移入 `m8`
（2 s 确认与 1 s 步长不兼容）。拿 2026-11-20 的 24 步旧记录对比会误以为"少跑了"。

**⚠ `t_seq m5` 结束后冒出的 `[Seq] Step 0 TIMEOUT` 是预期**（2026-11-23）：
`m5` 步 15 在 DONE 后又重按启动了一次，此时 `t_seq_auto=0`，角度条件永远不满足，
10 s 后必然超时。它打印在 `m5 done` **之后**，是"超时路径"被顺带验到，不是失败。
下一条脚本开头有 `t_arb clear` 或 `seq_abort` 即可，不必等它超时。

**⚠ `Requests/Rejects` 是"自本次上电累计"**（2026-11-23 实拍）：

`seq_control.c` 里这两个计数只 `++`、从不清零，`t_arb clear` 也清不掉。
连着跑 `m5` → `m11` 时，`m11` 的 `Requests` 从 **3** 起（m5 贡献 2 次），一路涨到 10。
`Complete/Abort` 才是本次序列计数。别把累计值当"这批多触发了 N 次"。

**⚠ `m10` 结束时整车停在 `ACC_ON`、母线 12.3 V**：

`t_veh_clr` 只清 FAULT，ACC 还在就回 `ACC_ON`；但 12.3 V < 13.0 V 永远上不了 `STARTED`。
R1-2 时后面五个脚本没跑 `t_bench` 仍全过，是"绕过门 2 + D-11 读到旧副本"两条叠加；
D-11 已修，现在只剩门 2 挡真实按键。
**凡是要用 `t_sim key mid pulse` 的脚本，前面必须 `t_bench`**，否则事件在门 2 被静默丢掉
（`drop evt 0x7000: vehicle not started`），表现为"按了没反应"。

**⚠ D-11 修完后：含一键步骤的脚本必须先 `t_bench`**（2026-11-23）：

`m5` / `m11` / `m13` / `m14` 里有一键或回位步骤。前置条件现在直接读 `vehicle_is_started()`，
不先 `t_bench` 会连续打印 `[Seq] Precondition fail: not started` 并返回 `-2`。
`m15` / `m16` 只有手动与 `LIMIT_HOLDING`，不受影响。
这不是回归——修复前它们能在未启车时跑通，本身就是 D-11 的假通过。

**⚠ 未对齐时欠压也会整条覆盖快区**：`[UV] snapshot saved: ... valid=0x00` 是预期
（脚本没跑 `focmode 3`），但它会写出一条 `src=FLASH / snap_seq=N` 的"看着正常"的记录。
批次 4 的加载器必须判 `valid` 位，不能只看 `src`。
