# 测试用例：批次 1（存储与参数）+ 批次 2（欠压与急停）

- 固件：`Debug/rtthread.elf`（2026-11-20 14:37，GCC 10.3.1）
- 适用版本：批次 1 + 批次 2 已合入；VOFA 当前为**关闭**状态（`FOC_VOFA_ENABLE=0`），属有意
- 目的：验证新增的 5 个欠压参数、快区新布局与上电预擦除；验证欠压状态机、急停、存档、门禁、上报
- **烧录前必须全片擦除**：`PARAM_MAGIC_SYSTEM` / `PARAM_MAGIC_FAST` / `PARAM_FAST_REC_MAGIC` 均已变更，旧记录一律判无效

## 0. 测试前置

| 项 | 要求 |
| --- | --- |
| 电源 | 可调直流电源（12~14 V）最好；没有则用「配置门限法」（见 B1 备选） |
| 调试口 | RTT Viewer / SEGGER RTT，能看 `rt_kprintf` |
| CAN | 可选：CAN 分析仪或 HMI，用于看 `0x18FF11D1` 电源状态位（无仪器则跳过 B6） |
| 钥匙 | 做 B7 需要能真实开关 ACC 钥匙 |
| 状态 | 电机可空载；**不要带载做 B2 的急停** |

`[PARAM]`、`[SYS-VOLT]`、`[UV]`、`[app_main]`、`[FOC-RUN]`、`[FOC-PROC]`、`[CFG]`、`[TICK]`。

## A. 批次 1：存储与参数

### A1. 启动自检打印（每次上电都应有）

```
（上电，等 2 s）
t_param info
```

**预期**

1. 启动日志里有 `[PARAM] ===== storage status =====` 段落，逐组打印
   `name rec=<字节>B sec=<扇区> cur=<扇区> left=<剩余>/<容量> erase=<次数> seq=<序号> wr=<次数> src=<FLASH|DEFAULT>`。
2. **`system` 组 `rec=148B`**、**`fast` 组 `rec=52B`**（这是批次 1 的布局变更，是重点）。
3. `motion` 组 `rec=116B`、`angle_mech` 组 `rec=76B`、`device` 组 `rec=108B`（未变）。
4. 首次烧录后：`motion`/`system` 应为 `src=FLASH`（初始化时已落默认值），`angle_mech`/`fast` 可能为 `DEFAULT`。

### A2. 新增 5 个欠压参数可见且默认值正确

```
t_param values
```

**预期**：`system` 段落中出现 5 行（顺序按 `s_system_ids[]` 排在末尾）：

```
0x0B02 uv_enter_mv    = 11000
0x0B03 uv_recover_mv  = 12000
0x0B04 uv_confirm_ms  = 30
0x0B05 uv_recover_ms  = 500
0x0B06 uv_blank_ms    = 200
```

补充：`t_cfg list | get 0x0B02` 也应能查到同名项，`def` 列与上表一致。

### A3. 改值 + 落盘 + 重启保持（Flash 优先于宏默认）

```
t_cfg set uv_enter_mv 10500 save
t_cfg get uv_enter_mv
t_param values
（断电重启）
t_param values
```

**预期**

1. `t_cfg set` 后打印成功；`t_cfg get` 的 `value=10500`、`src=FLASH`。
2. 重启后 `t_param values` 中 `uv_enter_mv = 10500`（**不被宏默认 11000 覆盖**）。
3. 最终恢复默认：`t_cfg default uv_enter_mv save` → 再 `t_cfg get uv_enter_mv` 应为 11000。

### A4. 恢复默认值（宏默认值生效）

> 注意：`t_param erase` 是**格式化语义**——擦除后把**当前 RAM 值**重新写回，不会恢复默认值。
> 要回宏默认值必须用 `t_cfg default`。

```
t_cfg set uv_blank_ms 800 save
（断电重启，确认 800）
t_cfg default all save
（断电重启）
t_param values
```

**预期**

1. `default all save` 后立即 `t_param values` 应全部回到默认；重启后仍是默认。
2. `uv_blank_ms = 200`，其余 uv 参数回 11000/12000/30/500。
3. 可选：`t_param erase all confirm` → 5 组 `seq=1`、`erase=1`、`left` 复位；但参数值仍是"擦除前 RAM 值"（格式化语义，不是恢复默认）。

### A5. 快区上电预擦除（批次 1 关键项）

```
t_param info
```

先记下 `fast` 组当前的 `seq` / `left` / `erase`（下面称 S0 / L0 / E0，`left` 形如 `185/186`）。

```
t_param fill fast 0
t_param info
（断电重启，观察启动日志）
t_param info
```

**预期**

1. `fill fast 0` 结束时 `left=0/186`（写入约 186 条），`seq` 增加约 186。
2. 启动日志出现两行：
   ```
   [PARAM] fast pre-erase: slots_left=0, saving once (cur=61)
   [PARAM] fast pre-erase done: left=185/186 cur=61 erase=<E0+1>
   ```
   `cur` 可能不是 61（取决于之前轮转到哪个扇区），只要 `erase` 比原来 +1 即正确。
3. 重启后 `t_param info`：`left=185/186`，`erase` +1，`seq` 继续 +1（预擦除写的那一条）。

### A6. 快区新字段打印

```
t_param
```

**预期**：`fast` 段落打印新布局，形如：

```
[PARAM] fast id=0x46415332
  valid=0x00 src=0 cpr=4096 pole=10 dir=1
  offset=0 fp=0 calib=0 snap_seq=0
  tube_x10=0 diff_tol=5 counts
```

- `id` 必须是 **0x46415332**（"FAS2"）；若仍显示旧值说明烧的是旧固件。
- `plate`：`cpr=4096`、`pole=10`、`diff_tol=5` 为默认。

### A7. 存储回归（确认批次 1 没破坏其他组）

```
t_mech
t_mech_check
t_param save all
t_param info
```

**预期**：`t_mech` 正常打印 active 行；`t_mech_check` 无错误；`save all` 后 `motion/system/angle_mech/device` 的 `seq`/`wr` 各 +1（`fast` 只有显式 `fast` 才写）。

## B. 批次 2：欠压与急停

### B0. 启动日志与参数打印

```
（上电，看启动日志）
```

**预期**：在 `[app_main] Started` 之后不久出现：

```
[SYS-VOLT] UV monitor: enter=11000mV confirm=30ms blank=200ms
[SYS-VOLT] UV hysteresis: recover=12000mV after 500ms
```

（若 A3/A4 改过参数，这里显示的是当前配置值。）

**同时确认**：正常 12 V 上电、消隐 200 ms 结束后**不应**出现 `[app_main] UV enter`。

### B1. 欠压进入（两种做法，任选）

**方案一：真实调压（推荐）**

```
（保持 msh 可用，电源 13.0 V）
（把电源调到 10.8 V，并保持 ≥1 s）
```

**方案二：配置门限法（无调压电源时）**

> 注意：欠压模块在**首次 10 ms 回调**时缓存参数，运行时改配置**不会生效**，必须重启。

```
t_cfg set uv_enter_mv 14000 save
t_cfg set uv_recover_mv 14500 save
（断电重启；12.3 V 输入会被判成"欠压"，且因为 recover=14.5 V 高于母线而保持欠压不振荡）
```

**预期（两方案相同）**

```
[app_main] UV enter: bus=10800mV -> emergency stop
[UV] snapshot saved: seq=1 off=<0..4095> dir=1 valid=0x00
```

同时：

- 回转侧：FOC 输出停止、抱闸锁止（听/看是否锁住）。
- 举升侧：阀关闭（若之前开过阀，应先开阀再测）。

**恢复配置**（方案二做完务必执行，然后重启）：

```
t_cfg set uv_enter_mv 11000 save
t_cfg set uv_recover_mv 12000 save
（断电重启）
```

### B2. 欠压期间门禁（本次重点）

在**保持欠压**的状态下（方案一的电源仍在 10.8 V；或方案二重启后仍处 UV）：

```
focmode stat
focmode 9 100
focmode 10 0
focmode 2 1 1.5
focmode 0
fstat
t_abz
t_param info
```

**预期**

| 命令 | 预期 |
| --- | --- |
| `focmode 9 100` | `[FOC-RUN] refuse mode 9: undervoltage`，模式不变 |
| `focmode 10 0` | `[FOC-RUN] refuse mode 10: undervoltage` |
| `focmode 2 1 1.5` | `[FOC-RUN] refuse mode 2: undervoltage` |
| `focmode 0` | 正常执行（`-> mode 0 (IDLE, all low)`） |
| `focmode 3` | `[FOC-PROC] refuse proc 3: undervoltage` |
| `fstat` / `t_abz` / `t_param info` | 正常输出（只读诊断放行） |

补充（锁轴模式是否放行，请记下实际行为）：`focmode 1 5` —— 规格为**放行**（LOCK 属静态输出），预期正常进入。

### B3. 存档"只写一条"（验证我修的那处）

在 B1 触发欠压**之前**先记录基线：

```
（正常上电后）t_param info
```

记下 `fast` 组的 `seq`（S1）、`wr`（W1）、`left`（L1，如 `185/186`）。

然后触发一次欠压（B1），再查：

```
t_param info
t_param values
```

**预期**

- `fast`：`seq = S1+1`、`wr = W1+1`、`left = L1-1`（**只减 1**；若减 2 说明又写成两条，需回报）。
- `t_param values` 的 fast 段：`snap_seq` 从 0 → 1；`valid` 取决于本次上电是否做过两点式对齐（没做过应 `0x00`）。
- `system` 组不受影响（欠压不写慢区）。

> 比较时排除另一种 +1：如果这次重启刚好触发了**上电预擦除**（见 A5 的两行日志），`fast` 的 `seq` 也会 +1 且 `erase` +1。判定方法是看启动日志有没有 `[PARAM] fast pre-erase`：有则本次 `seq` 预期 = S1+2、`left` = L1-2（预擦除 1 条 + 存档 1 条），无则 = S1+1 / L1-1。

### B4. 恢复（迟滞 + 自动回到正常）

方案一（真实调压）：


**预期**

```

```

```

```

**预期**：不再被拒绝（`-> mode 9 ...`），说明门禁解除。**不会自动恢复动作**，需要重新给指令。

### B5. 消隐期不误报（上电瞬间）

```
（反复断电/上电 3 次，每次观察启动日志）
```

**预期**：每次上电都**不应**出现 `[app_main] UV enter`（除非确实欠压）。重点看 `[SYS-VOLT] UV monitor` 打印之后、200 ms 内没有 UV 行。

### B6. 状态帧电源位（需 CAN 分析仪/HMI；无仪器跳过）

触发欠压后，抓 `0x18FF11D1`：

- Byte0（或协议约定的电源状态位）应为 **01（欠压）**；恢复后回 **00（正常）**。
- 无仪器时用 `t_cantx` 确认 `11D1` 周期在跑、`ok` 计数递增即可。

### B7. ACC 下电急停、**不**存档（需钥匙）

前置：正常电压、FOC 处于一个正在输出的模式（例如 `focmode 1 5` 或 `focmode 2 1 1.5`），并开一下举升阀（按上升键或 `lift` 相关操作）。

```
（记录）t_param info
（关闭钥匙 ACC，观察日志）
```

**预期**

1. `[app_main] ignition key OFF -> gate1 closed, seq cleared`
2. 回转停、抱闸锁、举升阀关。
3. **不应出现** `[UV] snapshot saved`。
4. 再上钥匙后 `t_param info`：`fast` 组 `seq`/`wr` 与关闭前一致（说明没存档）。

**本轮发现并修复（15:06 固件生效）**

1. `t_abz` 用 `%.2f/%.1f` 打印，而本工程 `rt_kprintf` **未启用浮点** → 输出字面量 `%f`，且可变参数错位导致 `dir=536870188`。已改为整数定点打印并拆成两行（`cnt/rev/dir` 与 `mech/elec/rpm`）。
2. 门禁拒绝后 CLI 仍打印"成功"信息：`focmode 2` 会输出 `IF running...`，`focmode 9/10` 会打印参数表。已在 `case 2/4/9/10` 增加"是否真的进入模式"判断，打印 `xxx not entered (mode stays N)` 并跳过后续；被拒绝的 IF 还会清掉残留频率（否则 `fstat` 显示 `IF f=1.0 Hz`）。

观察项（非缺陷，记录备查）：

- `motion motor_pole_pairs = 4` 是旧机械表遗留值，FOC 实际用 `CFG_MOTOR_POLE_PAIRS=10`；快区快照写的是 10，两者不冲突（对应任务清单 §6-13 待确认项）。
- 每扇区槽位：`motion 70`、`angle_mech 107`、`system 55`、`fast 157`、`device 75`，与记录大小一致（扇区 8 KB）。
- `[FP] fast_x100=99900` 说明过流阈值仍是 999 A（P2-9 未整定，属已知）。

**顺手确认的存储口径（重要：别再把 `left` 当"还能存几次"）**

- `wr` 是**本次上电的写次数**：`Param_Init()` 里 `memset(rt, 0, ...)`，不持久化；
- `seq` 跨上电保持；
- 空片首次上电，`Param_Init()` 在**无有效记录**时会写一条 **`seq=0` 的默认记录**（`param_manager.c:161-165`），占 1 槽、不计入 `wr`。

因此稳定关系是：

```
left = 满槽位 − seq − 1
```

五组全部吻合：`70−1−1=68`(motion)、`107−1−0=106`(angle_mech)、`55−1−1=53`(system)、`157−1−2=154`(fast)、`75−1−1=73`(device)。
判定 B3"只写一条"要看 `seq`/`wr` 的增量，不能只看 `left` 减 1。

补充（2026-11-20 由 `param_manager.c:182` 证实）：空片写默认记录时也会 `write_count++`，所以稳定关系还有 **`wr = seq + 1`**。
例：`motion seq=1 wr=2`、`angle_mech seq=3 wr=4`、`fast seq=0 wr=1`。因此 `wr` 不能直接当"保存次数"，要减 1。

## G. ACC（钥匙）链路怎么测（台架/无钥匙）

**ACC 没有专用命令，但可以用输入模拟层 `t_sim` 直接给电平**（2026-11-20 新增，见 `任务清单.md` §11）：`t_key_state` / `t_key_state_clr` 已于 2026-11-14 删除（Q-67）；ACC 状态只来自 **PB0**（低电平有效、外部 10k 上拉、内部上拉关闭），由 `acc_poll()` 在 50 ms tick 里做双向去抖（`acc_enter_ms` / `acc_exit_ms`，默认各 500 ms，`CFG_F_REQ_RESTART` → **改后需重启**）。CAN 侧没有 ACC 信号，`0x18FF8380` 只带按键。

| 命令 | 作用 |
| --- | --- |
| `t_sim acc on` / `off` | 模拟钥匙上电 / 下电（**去抖仍生效，500 ms 后确认**） |
| `t_sim acc auto` | 回到真实 PB0 |
| `t_veh` | 打印 `state`、`started`、`acc_on`、`rpm_ms`/`volt_ms`、`fault_word`、`can_silent`、`rpm`、`volt`、`engine_running`、`counts` |
| `t_veh_clr` | `vehicle_force_reset()` → 整车对象强制回 OFF（**不改** `acc_on`，PB0 仍是钥匙真值） |

**台架模拟法（任选其一）**：① `t_sim acc on|off`；② PB0 对 GND 短接 = 钥匙 ON，断开 = OFF（外部上拉拉高）。

```
t_sim acc off              → 等 0.5 s：[ACC] OFF (PB0 high for 500ms)
t_veh                      → acc_on=0、state=OFF
t_sim acc on               → 等 0.5 s：[ACC] ON  (PB0 low for 500ms) → [app_main] ignition key ON
t_veh                      → acc_on=1、state=ACC_ON
```

**B7 完整做法（下电急停但不存档）**：

```
focmode 1 5                  ← 保持输出（5% LOCK）
t_param info                 ← 记下 fast 的 seq / wr / left
（断开 PB0 = 关钥匙）
  期望：[ACC] OFF → [app_main] ignition key OFF -> gate1 closed, seq cleared
        → [FOC-MODE] -> mode 0 (IDLE, all low) → [Swing] Locking...
        **不应出现** [UV] snapshot saved
（PB0 → GND = 上钥匙）
t_param info                 ← fast 的 seq / wr / left 与关钥匙前一致
```

注意：

1. 关钥匙瞬间若母线被拉到 <11 V 并持续 30 ms，会**同时**触发欠压存档，`fast seq` 会 +1——这不是 B7 失败；判定前先确认本轮没有 `[app_main] UV enter` 行。
2. 想验证门 1（`acc_is_on()==0` 拒绝动作），需要真实按键帧（`0x18FF8380`，可用 CAN 分析仪发）或新增调试命令；msh 目前没有直接入口，`focmode` 属 FOC 层，不受门 1 约束。
3. 若台架只有 12 V、又要满足"一键/离合需已启车"的前置条件：`t_sim bus 13200`（最省事，`vehicle_poll` 500 ms 后进 STARTED）；或 `t_cfg set veh_enter_volt_dv 120 save` 后**重启**（`vehicle_cfg_load()` 只在 init 读一次，默认 130 = **严格大于** 13.0 V）；或注入 `0x0CF00400` 转速 >400 rpm（`t_sim rpm 600`）。
