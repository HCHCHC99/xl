# 状态帧与灯帧

> 两条都是**本机发出、给外部设备看**的周期帧，不参与控制。
> 它们出了偏差不会让机构乱动，只会让人看到的与实际的不是一回事。
>
> 代码基线：`F:\xl_v\code\vl_v.2.1.6`（2026-11-23，P8 交付）

---

## 0. 一句话定位

| 帧 | ID | 周期 | 方向 | 谁在看 | 看什么 |
|---|---|---|---|---|---|
| 状态帧 | `0x18FF11D1` | 100 ms（相位 0） | UTMotVCU → HMI 显示屏 | 驾驶室操作员 | 角度、电机/举升在不在动、什么故障、什么模式 |
| 灯帧 | `0x18FFA4F0` | 100 ms（相位 50） | UTMotVCU → CPB 遥控器 | 手持遥控器的人 | 10 个按键灯 + 3 个指示灯 + 背景灯 |

相位错开 50 ms 是为了两条 100 ms 帧不在同一拍挤总线。

## 1. 状态帧 0x18FF11D1

### 1.1 字节布局

| 字节 | 字段 | 位宽 | 取值 | 数据源（P8 后） |
|---|---|---|---|---|
| B0 | `power_voltage_sta` | 2 | 00 正常 / 01 欠压 / 10 过压 | `sys_voltage_is_uv()` |
| B0 | `calib_sta` | 2 | 00 无 / 01 已校准 / 10 未校准 | `g_sys_params.is_calibrated` |
| B0 | `comm_sta` | 1 | 0 正常 / 1 故障 | `can_is_bus_silent(can_fault_ms=300)`（P10；任意帧） |
| B0 | `work_mode` | 3 | 000 待机 / 001 手动 / 010 一键展开 / 011 一键回位 | 见 §1.2 |
| B1 | `encoder_sta` | 1 | 0 正常 / 1 故障 | `g_swing_obj.ctx.encoder_fault` |
| B1 | `motor_sta` | 3 | 000 停止 / 001 左转 / 010 右转 / 011 开路 / 100 堵转 | 见 §1.3 |
| B1 | `lift_sensor_sta` | 1 | 0 正常 / 1 故障 | `g_lift_obj.ctx.sensor_fault` |
| B1 | `lift_sta` | 3 | 000 停止 / 001 上升 / 010 下降 | 见 §1.4 |
| B2 | `up_valve_sta` | 2 | 00 正常 / 01 开路 / 10 短路 | `g_solenoid.up_fault`（原始码） |
| B2 | `down_valve_sta` | 2 | 同上 | `g_solenoid.down_fault` |
| B3 | `teeth_set_sta` | 1 | 0 未设置 / 1 已设置 | `g_sys_params.teeth_type != TEETH_UNSET` |
| B3 | `teeth_code` | 2 | 0=13 齿 / 1=14 齿 / 2=11 齿 | `g_sys_params.teeth_type` |
| B4 | 保留 | 8 | 0 | — |
| B5-6 | `swing_angle_raw` | int16 | 物理角 = raw − 300（整度） | `swing_angle_get_value()` |
| B7 | `lift_angle_raw` | uint8 | 物理角 = raw − 90（整度） | `lift_angle_get_value()` |

角度换算：模块内部是 0.1°，帧里是整度。用**就近取整**（`(x+5)/10` / `(x-5)/10`），
避免 −0.4° 截断成 0 后与 `-300` 偏移叠加出现 1° 的边界跳动。

### 1.2 work_mode 的口径

这**不是** MAINT/WORK 那套系统权限模式（那是"当前能干什么"），
而是"控制器此刻在做什么动作"（那是"正在干什么"），两者不是一个维度。

推导优先级（`derive_work_mode()`）：

```
序列引擎在跑 && current_onekey == 3            → 011 一键回位
序列引擎在跑 && current_onekey == 1 或 2       → 010 一键展开
任一手动轴在 RUNNING，或任一手动键正被按住      → 001 手动
其余                                          → 000 待机
```

对应 TC-ONE-017（执行中 = 010 / 回位 = 011 / 结束后 = 000 或 001）。

### 1.3 motor_sta 的口径

```
motor_stall_is_faulted()          → 100 堵转（最高优先）
swing 状态 == H_STATE_LEFT_RUNNING  → 001 左转
swing 状态 == H_STATE_RIGHT_RUNNING → 010 右转
其余                              → 000 停止
```

**011「开路」没有数据源**：那是电机三相开路检测，本工程尚未实现，留空。

**D-1 已修**：以前限位拦截/零位重触发/模式拒绝时，`enter_left_running`
只 `LOG_WARN + return`，但跳转表已经把状态迁到了 `LEFT_RUNNING` ——
状态帧接真实值后 HMI 会误报"电机在转"。现在拦截时同步投一次"松手"
（`RUNNING → LOCKING → IDLE`），顺带把刹车重新锁上。

### 1.4 lift_sta 的口径

```
P_STATE_UP_RUNNING      → 001 上升
P_STATE_DOWN_RUNNING    → 010 下降
P_STATE_LIMIT_HOLDING   → 按 hold_direction 报 001 / 010
其余                    → 000 停止
```

`LIMIT_HOLDING` 是 P6 加的"到限位后继续通电 5 s"（TC-MAN-008）。
那 5 秒里阀确实还带着电，所以**按实际通电方向报**，而不是报"停止"——
状态帧回答的是"控制器在做什么"，把保压藏成"停止"会让 HMI 与实际不符。

### 1.5 与旧实现的差别

旧实现是"事件驱动单字段刷新"：9 个字段各等一个 `CAN_EVT_STA_*`。
实际后果是只有 `POWER / CALIB / VALVE / TEETH` 四条有人投递，其余六条
（comm / work_mode / encoder+motor / sensor / lift / angle）**全工程零投递**，
永远停在 `reset_default()` 的初值 —— 屏上看到的是
"角度恒 0°、电机恒停止、举升恒停止、模式恒待机、通信恒正常"。

P8 改成 50 ms tick 调 `status_tx_refresh()` 全量读 getter。
`pack` 仍只 `memcpy`，发送线程不访问别的模块（线程约束不变）。
`status_tx_on_event()` 保留，内部等同一次 refresh。

## 2. 灯帧 0x18FFA4F0

### 2.1 字节布局

每键 / 每灯 **4 bit**：`bit0 = 绿`、`bit1 = 黄`、`bit2 = 红`、`bit3 = 闪烁`。

| 字节 | 低半字节 | 高半字节 |
|---|---|---|
| B0 | 按键1 上 | 按键2 下 |
| B1 | 按键3 左 | 按键4 右 |
| B2 | 按键5 一键回位 | 按键6 校准 |
| B3 | 按键7 一键右中 | 按键8 一键右后 |
| B4 | 按键9 离合结合 | 按键10 离合分离 |
| B5 | 保留 | 保留 |
| B6 | 指示灯1 电机 | 指示灯2 控制器 |
| B7 | 指示灯3 传感器 | bit4 = 背景灯（1 bit），bit5-7 保留 |

### 2.2 分层（P8 的关键改动）

```
led_effect.c        纯决策：读各模块 getter → 每键 4bit + 判定依据
      ↓
led_tx.c            把结果写进 8 字节位域 → can_tx 周期发送（可关）
      ↓
t_led               RTT 直接打印决策结果，完全不碰总线
```

灯色的本质是「状态 → 4bit」，与「这 8 字节怎么发出去」是两件事。
混在一起时，台架上想验"编码器故障该亮红闪"就必须先让整条 CAN 链路通。
拆开后 `CAN_TX_EN_LED = 0`（总线静默）时 `t_led` 照样能验全部规则。

### 2.3 规则表

优先级 **红 > 黄 > 绿**（TC-LED-011）；闪烁位可叠加。

| 对象 | 规则 | 用例 |
|---|---|---|
| 左 / 右转键 | 编码器故障 → 红闪；电机堵转 → 红常亮；该方向有输出 → 黄常亮；其余绿 | LED-001/002 |

> **`encoder_sta` / 编码器红闪的写入来源（2026-11-23 补齐）**
>
> 只有一个真实生产者：`swing_angle_update()` 判出"解算 有效→无效"时，经
> `on_fault_change` → `swing_angle_fault_to_ctx()` 写 `ctx.encoder_fault`；
> 恢复（无效→有效）时清 0 并投 `SWING_EVT_ENCODER_FAULT_CLEAR`。
> `t_encfault` 是台架旁路，直接写同一字段。
>

> `enc_rep=0` 而 `t_sta` 的 `enc=1`，说明是 `t_encfault` 注入的。
>

| 上升 / 下降键 | 该路阀开路 → 红闪；短路 → 红常亮；该方向有输出（含限位保压）→ 黄；其余绿 | LED-003/004 |

> **阀故障取「去抖确认后」的码**，不是 CAN 原始码。P4 做了 500 ms 去抖，
> 若灯和状态帧读原始码，就会红闪一下又变绿，比不去抖更困惑。
> 三者（灯 / 状态帧 / 举升状态机）口径必须一致：
> `lift_control_valve_fb_get()` 的 `latched=1` 才认，`latched=0`（含去抖窗口内）报正常。
| 一键三键 | 该键对应序列在跑 → 绿闪；其余绿 | LED-005 |
| 校准键 | 未校准 → 黄常亮；已校准 → 绿 | LED-006 |
| 离合两键 | 本机不驱动离合电机 → 绿占位 | LED-007 |
| 电机指示灯 | 堵转 / 编码器故障 → 红闪；其余绿 | LED-008 |

| 背景灯 | 恒亮（1） | LED-010 |

### 2.4 协议限制：闪烁频率表达不了

每键只有 1 个闪烁位，**没有频率字段**。用例里的
「红 1Hz」（编码器故障）与「红 5Hz」（电机堵转）在实际帧上是同一个编码 `0x0C`，
频率由面板固件自行决定。这是硬件协议的限制，不是实现取巧。

#### 2.5.1 "1 Hz / 5 Hz" 的协议层依据，以及它自相矛盾

| 位置 | 原文 |
|---|---|
| `00_说明与约定` **R48 / B48**（"灯控制"行） | "4 位字段依次控制绿、黄、红、闪烁；**闪烁频率 1 Hz 或 5 Hz**；优先级 红>黄>绿" |
| `02_信号定义` **R36–R45**（0x18FFA4F0，每个半字节一行） | 每键的 4 位只定义 **"绿／黄／红／闪烁"**，**没有频率位** |

也就是说：**帧上只能表达"闪 / 不闪"，表达不了"以几 Hz 闪"**。
用例里的 1 Hz（编码器故障、通讯故障）与 5 Hz（校准执行中、堵转）在
`0x18FFA4F0` 上是**同一个编码**（`0x0C` 红+闪 / `0x09` 绿+闪），控制器无法区分。

三种可能的收口方式（P9 之前需定，否则校准灯只能验"闪/不闪"）：

| 方案 | 做法 | 代价 |
|---|---|---|
| A. 频率归面板固件 | 控制器只发"闪/不闪"，1 Hz 与 5 Hz 由遥控器固件决定 | 零改动，但用例的"5 Hz"永远无法由本机保证；需向面板方确认各灯色的实际频率 |
| B. 控制器翻转 bit3 | 按目标频率每 100 ms 帧交替置/清 bit3，让"闪烁位"本身就是 1 Hz/5 Hz 的方波 | 若面板固件自己也做闪烁，会叠加成怪频率；必须先确认面板行为 |
| C. 扩协议 | 借用保留位（`Byte5` 整字节预留）承载频率 | 需面板同步改；跨方协调成本最高 |

> 当前实现取 **A**（只发"闪/不闪"），并在 `t_led` 的判定依据里标注语义
> （`red-blink` / `green-blink`），不承诺频率。

## 3. msh 命令

| 命令 | 作用 |
|---|---|
| `t_sta` | 打印状态帧：id / 周期 / 相位 / 8 字节 raw / 逐字节解码 / 输入快照 |
| `t_sta <n>` | 连打 n 次（上限 10），间隔 500 ms，用来看变化 |
| `t_led` | 打印灯帧：id / 周期 / 相位 / 8 字节 raw / 每键灯色 + 判定依据 / 输入快照 |
| `t_led <n>` | 同上 |
| `t_comm` | **P10 新增**：通信静默诊断。无参打印 `age/thr/state`；`test` 在无总线下验 250 ms→ok、350 ms→FAULT；`age <ms>` 拨"最近一帧"时刻（台架） |
| `t_encfault <0\|1>` | **注入/清除编码器故障**：0=正常、1=故障。只写 `g_swing_obj.ctx.encoder_fault` 一个标志，**不驱动状态机**（可随时清 0，不留 `H_FAULT` 残留）。需 `DIAG_WRITE`。编码器故障**不分级**（SPI/RS485 断线、ABZ 无脉冲同处置：停机+关阀+抱闸+拦一键，手动保留），所以只有 0/1 |
| `t_sim clear swing` | **让解算真的失效**（关掉台架模拟，回到真实解算路径）。这是验证"真实上报链路"的手段——`t_encfault` 只写标志，验不到 `swing_angle` → `ctx.encoder_fault` 这一段。恢复用 `t_sim swing <x10>` |
| `t_seq m19` | 把上一条的完整流程串成 21 步（失效→上报→一键被拒→恢复→故障中手动），2026-11-23 新增 |
| `t_seq m17` | 把 §4.2 的注入表串成 53 步脚本，一条命令跑完 |
| `t_cantx` | 发送槽位总表（只在看 `ok/err` 计数、有没有注册时用） |

两个命令都是只读，不要求 `DIAG_WRITE`（与 `t_cantx` 一致）。

## 4. 台架怎么验

### 4.1 只看决策，不看总线

把 `applications/CAN/can_tx_cfg.h` 的两个宏置 0：

```c
#define CAN_TX_EN_STATUS        0
#define CAN_TX_EN_LED           0
```

上电会打印：

```
[CAN-TX] status frame DISABLED by can_tx_cfg.h (t_sta still works)
[CAN-TX] led frame DISABLED by can_tx_cfg.h (t_led still works)
```

此时 `t_cantx` 显示 slots=1（只剩阀帧），但 `t_sta` / `t_led` 输出完全不变，
且 `send: OFF` 一行会明确标注。验完改回 1 即可，无需改任何逻辑代码。

### 4.2 逐项注入与期望

> **偷懒办法**：下面两张表已串成 `t_seq m17`（53 步，约 53 s），一条命令跑完 8 段。
> 逐项表用于出问题时定位是哪一步。

| 想验什么 | 怎么做 | `t_led` 期望 |
|---|---|---|
| 左转有输出 → 黄 | `t_sim key left hold` | `left : 0x2 yellow <- output on` |
| 松开 → 绿 | `t_sim key none` | `left : 0x1 green <- idle` |
| 编码器故障 → 红闪 | `t_encfault 1` | `left/right : 0xC red-blink <- encoder fault`；`motor : 0xC`；inputs 行 `enc=1` |
| 上升阀开路 → 红闪 | `t_sim valve 1 0`（等 500 ms 去抖确认） | `up : 0xC red-blink <- valve open` |
| 上升阀短路 → 红常亮 | `t_sim valve 2 0` | `up : 0x4 red <- valve short` |
| 未校准 → 校准键黄 | `t_param` 或清校准标志 | `calib : 0x2 yellow <- not calibrated` |
| 一键在跑 → 该键绿闪 | `t_seq_run mid` | `mid : 0x9 green-blink <- sequence running` |
| 传感器故障 → 传感器灯红 | `t_sim lift 4800` 保持 2 s | `sensor : 0x4 red <- sensor fault` |
| 通信静默 → 控制器灯红闪 | `t_sim cansilent 1` | `ctrl : 0xC red-blink <- comm fault` |

状态帧同理，用 `t_sim` 改输入后 `t_sta` 看解码：

| 想验什么 | 怎么做 | `t_sta` 期望 |
|---|---|---|
| 角度 | `t_sim swing 1200` / `t_sim lift 3768` | `swing = 120.0 deg` / `lift = 42.9→43.0 deg` |
| 模式 | `t_seq_run mid` | `mode=010(onekey-expand)` |
| 模式 | `t_seq_run home` | `mode=011(onekey-home)` |
| 模式 | `t_sim key left hold` | `mode=001(manual)` |
| 电机 | `t_sim key left hold` | `motor=001(left)` |
| 举升 | `t_sim key up hold` | `lift=001(up)` |
| 限位保压 | 上升到上限后 5 s 内 | `lift=001(up)`（阀仍通电） |
| 阀故障 | `t_sim valve 2 0` | `up_valve=10(short)` |
| 欠压 | `t_sim bus 10000` | `power=01(undervoltage)` |
| 通信 | `t_sim cansilent 1` | `comm=1(FAULT)` |

### 4.3 `t_seq m17` 分段

| 段 | 步数 | 内容 | 关键判据 |
|---|---|---|---|
| A 基线 | 4 | `t_sta` / `t_led` 各一次 | 角度真实值、`mode=000`、全绿 |
| B 手动 | 10 | 左转 + 上升各一次 | `mode=001`、`motor=001`、`lift=001`；两键黄 |
| C 阀故障 | 7 | 开路 → 短路 → 清除 | `up=0xC` → `0x4` → `0x1`；`up_valve=01→10→00` |
| D 一键 | 6 | `t_seq_run mid` → `seq_abort` | `mode=010`；`mid=0x9` → `0x1` |
| E 传感器 | 9 | `lift 4800` 保持 → 恢复 | 2 s 后 `sensor=1` 灯红；恢复后回绿 |
| F 编码器 | 5 | `t_encfault 1` → `0` | `enc=1`；左右键与电机灯 `0xC`；清 0 后回绿 |
| G 通信静默 | 5 | `t_sim cansilent 1/0` | `comm=1`；`ctrl=0xC` → 回绿 |
| H 欠压 | 4 | `bus 10000` → 13200 | `power=01` → `00` |
| 收尾 | 3 | `t_veh_clr` + `t_sta` + 复位角度 | 清掉 G 段进入的 FAULT；`mode=000`、`power=00`。ACC 仍 on，日志会紧接 `ACC_ON → STARTED`，属正常 |

跑法：

```
t_bench        # 必须先跑：起车 + cansilent 0 + 13.2V
t_seq m17      # 53 步，约 53 s
```

> **2026-11-23 实测：53 步全部通过。** 收尾 `t_veh_clr` 后会紧跟
> `ACC_ON → STARTED`（ACC 与母线仍在），这是正常的，判据看 `t_sta` 的
> `mode`/`power`，不要看整车状态。

两点提醒：

- 1 s 步长下，2 s 类判据只能看「已/未确认」，精确时序仍以 `m8` 为准。
- G 段 4 步 = 3 s > `veh_fault_ms`(2000)，整车会进 `FAULT`；这是预期，脚本末尾 `t_veh_clr` 复位。
- E 段第 2 次 `t_lift` 落在 1950 ms 边界，显示「未确认」属正常，第 3 步才变。

### 4.4 有 CAN 仪时

接 250 kbit/s，看 `0x18FF11D1` / `0x18FFA4F0` 每 100 ms 一帧，
字节应与 `t_sta` / `t_led` 的 `raw` 行逐字节一致。
这是唯一能同时验证"决策对"和"传输对"的方法。

## 5. 已知限制

1. **角度精度是整度**：帧里 `swing_angle_raw` / `lift_angle_raw` 各占 1 字节
   量级，物理值只能是整度。0.1° 的分辨率在协议层面就丢了。
2. **`motor_sta` 的 011「开路」**无数据源（需要三相开路检测），永远不报。
3. **`lift_sta` 在 `FAULT_VALVE` / `FAULT_SENSOR` 时报 000**：这两个状态下
   阀被强制关断（或手动放行但无限位），没有稳定的方向可报。
4. **`comm_sta` 用"任何帧静默"判据，门限是独立的 `can_fault_ms=300`**（P10），
   与整车 FAULT 的 `veh_can_silent_ms=500` + `veh_fault_ms=2000` **不同源**：
   300 ms 只让状态帧报故障、控制器灯红闪；整车 FAULT 仍要 2.5 s。
   单个节点掉线（比如 RGV 不发）在总线上还有别的帧时不会触发。
5. **灯色待确认 4 条**见 §2.5，实现里已按最保守方式占位。
6. **状态帧角度在传感器故障时是冻结值**：`lift_angle_get_value()` 返回最后一次
   可信值，此时 `lift_sensor_sta = 1` 表示"这个角度不可信"。HMI 需要同时看这两位。
